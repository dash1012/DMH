면접은 이렇게 진행돼요

형식

  • 학생 1명 : 면접위원 2~3명
  • 1인 약 10분(±2분) → 질문은 보통 5~7개
  • 답 하나는 1분 안팎. 길어지면 질문 수가 줄어 보여줄 기회도 줄어요.
  • 자소서·상장 사본·취업(창업)계획서를 바탕으로 질문

평가요소 3가지

  • 진로목표·학업역량 — 관심 분야, 해 온 공부, 전공 역량, 배우고 싶은 것
  • 인성 — 가치관, 책임감, 성실성, 존중과 배려
  • 단체생활 적응력 — 규칙 준수, 원만한 관계, 협력
대회입상 부문의 핵심
"상을 받을 만한 실력이 있는지"를 확인해요. KOI 2차 장려상이라면 알고리즘 개념을 직접 설명할 수 있어야 하고, 결과물보다 "왜 그 방법을 골랐는지, 다른 방법과 비교하면 장단점은?"을 물어요.

모든 경험은 이 5단계로 말하기

01
활동 동기 — 왜 시작했나
02
수행 과정 — 무엇을 어떻게 했나
03
본인의 역할 — 내가 직접 한 것 (팀원이 한 건 정직하게 구분)
04
문제 해결 과정 — 막혔던 점과 해결 방법
05
결과·배운 점 — 숫자나 변화로 + 한 줄 교훈

내 경험 한눈에 보기

경험동기내 역할문제 해결결과·배운 점
KOI 준비원리로 푸는 재미, 탐색 횟수 줄이기혼자삼중·사중 반복문 시간 초과 → 곱의 법칙 공식 / 그리디 공부1차 동상 → 2차 장려상 / 수학은 코딩의 도구
AI 용돈기입장친구들 충동구매혼자 기획·개발학생 확인친구들 소비 습관 변화
EMO 시스템방치 킥보드 문제동아리장, 흐름 기획변수명 충돌 → 규칙 통일완성 / 협업·기획의 중요성
탁구부인원 부족, 5:0 패배제안, 일정 조정, 서브 리시브 지도 / 내 자세는 교정받음실력 차이를 서로 코치로재경기 4:1 / 존중과 협력

지킬 것

  • 첫 문장에 결론, 그다음 근거 경험 1개
  • 모르면: "정확히는 모르지만, 제 생각에는…" 하고 생각 과정을 말하기
  • 팀 프로젝트는 "제가 한 부분 / 팀원이 한 부분"을 구분
  • 답이 자소서·창업계획서와 어긋나지 않게

피할 것

  • 하지 않은 일, 모르는 개념을 아는 척하기
  • 도구 이름만 나열 (특히 "AI로 다 만들었다"로 들리는 말)
  • "학원"이라는 단어
  • "아마 ~할 것 같습니다" 같은 흐린 끝맺음

학교 공식 안내에서 꼭 기억할 것

  • 실제 기출(2026): "전공 역량으로 볼 때 ○○과에 합격할 자격이 있는 이유는?", "가장 열심히 공부한 과목과 그 이유는?" (A1, A2)
  • 진로·학업역량에서는 특정 과목에 관심을 가진 이유, 나의 강점 전공 역량, 앞으로 배우고 싶은 분야를 물을 수 있어요. (A2, A1, V3)
  • 심화질문 예시는 기출이 아니라 질문 방향이에요: "현재의 코드 구조·구현 방식을 고른 이유와 장단점은?" → 내 실적으로 바꾼 것이 S1~S6
  • 결과물을 만든 사실보다 제작 과정의 판단, 기술에 대한 이해, 다른 방법과 비교한 선택 이유를 확인해요.
  • 정답을 외우기보다 동기 → 과정 → 역할 → 문제 해결 → 결과·배운 점을 내 말로.

질문 목록에서 평가: 진로·학업역량 / 인성 / 단체생활 필터로 평가요소별로 모아 볼 수 있어요.

면접위원은 자소서를 보며 질문해요. 밑줄 친 문장을 누르면 그 문장에서 나올 질문이 보이고, 바로 답안으로 이동할 수 있어요. 질문이 많이 걸린 문장일수록 진하게 표시돼요.

자소서와 면접 답이 어긋나기 쉬운 곳
  • 자소서는 "그리디를 깊이 공부했다"고 했지만 예시는 곱의 법칙(그리디 아님) → 둘을 구분해서 설명 (K5)
  • 작품 이름이 "AI 용돈기입장"인데 설명은 RFM 수식 → AI가 실제로 한 일을 정확히 (S6)
  • "후배들이 AI와 소통하며 구현" → "그럼 이해 못 하고 쓴 거 아니냐"는 질문 대비 (S5)
  • 탁구부에서 나도 자세를 교정받았다는 점 — 가르치기만 한 사람처럼 말하지 않기 (C1, C5)
  • 자소서 2번은 "이끌었다", 코드페어 리더는 친구 → 역할 답을 항상 같게 (B1, R4, G3)
